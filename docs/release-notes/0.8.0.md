# Cast v0.8

The native control panel now puts output tasks first. Operate has four permanent
cards with direct virtual-camera, recording, streaming and audio actions. A slim
privacy/preview/close header replaces the lane chips. Streaming setup is the first
action when no destination is configured; connection state remains separate from
the explicit action that reveals composition.

Compose has six focused pages, with Essentials first and one All settings
disclosure for the remaining controls. Layout diagrams, an eight-point camera
anchor grid, segmented toggles, sliders, scrollable device/enum pickers, swatch/hex
color pickers and one annotation matrix replace repetitive browsing controls.
All 149 existing settings have one home. Recording configuration lives on the
Recording card, audio settings on Audio, and streaming fields in setup.

Camera and stage size sliders keep dragging local, then send one acknowledged
setting update on release. This updates active outputs and preview together.
Other composition fields retain pinned Apply/Revert drafts. Pages, scroll and
All settings state are remembered for the same daemon session without writing
configuration. Lane links in the status bar jump to their task cards.

The daemon, IPC command names and floating preview remain unchanged. Privacy
restoration, pause/freeze/blur layering, same-file recording cut/resume, countdown
exclusion and reconnect behavior retain their existing semantics. Closing the
panel only closes that window.

No configuration fields are added. Existing released configuration files need no edits.
Configs from the earlier unreleased overlap-policy experiment must remove
`[capture] exclusion`; keep `mask_color` for opaque masking.
Pause/blur output fonts remain configured through the file; the panel itself uses
only bundled Inter. Dragging the camera in preview and preview-only geometry
updates are not implemented. Device choices come from existing discovery commands.
Monitor/region masking cannot reconstruct desktop pixels hidden by the controls;
Wayland keeps its existing capture and native-preview limitations.

Release assets target current Arch Linux x86_64 and include Xorg, Wayland and panel
support. Installation dependencies and virtual-camera setup remain unchanged;
packages neither create devices nor start services automatically.

Verification: full Xorg/Wayland/panel build and routes with `-Werror`; `make check`
(unit, IPC, decoded media/privacy, stream networking and mock portal tests); Xorg
capture checks with and without MIT-SHM; countdown/recording exclusion; native
panel workflows at 1× and 2× density over 360–800px widths; Xorg color validation
and annotation matrix; pointer drag/release transaction checks. The native design
was inspected in one screenshot batch and one confirmation after scoped fixes.
