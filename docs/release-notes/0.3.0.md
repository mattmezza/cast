# cast v0.3

The panel and output preview now declare the Xorg utility window type before
mapping, retaining their CastPanel and CastPreview classes. Window managers that
float utility windows, including mwm, center them automatically.

- Square panel controls, consistent drawn line icons and a clearer Back control
  improve navigation without hiding action labels or keyboard focus. The output
  preview remains visible and movable across sections.
- The standalone preview follows the output frame rate, reuses conversion storage
  and keeps a bounded latest-frame queue rather than accumulating latency.
- Keystrokes retain a bounded recent history for three seconds by default
  (`keys.timeout_ms`). Consecutive observed presses collapse as `j`, `jx2`, `jx3`.
  Privacy and source changes still clear annotation history.
- A recording countdown displays a simple numbered film-style guide in the panel.
  Without an attached panel, Xorg shows a centered local countdown window. Escape,
  closing that window, `cast record stop` or `cast pause` cancels the pending start.
  The guide is excluded from screen capture and disappears before recording starts.

The Arch x86_64 package includes Xorg, Wayland and panel support. Use the README's
curl installer or `cast update v0.3`; stop the daemon before upgrading and restart
it afterwards. Existing configuration remains unchanged. Older manual installations
in /usr/local/bin can take priority over /usr/bin/cast.

Wayland uses the panel countdown guide; a standalone countdown window and capture
exclusion remain unsupported there. The package targets current Arch library ABIs.

Validation: combined and Wayland-only builds pass with compiler warnings treated
as errors, together with native panel checks at 1x and 2x, private mwm placement,
Xorg capture with and without shared memory, recent-key visual/sanitizer tests,
real-daemon countdown cancellation and decoded first-frame exclusion. The isolated
60 Hz preview comparison improved from 20/90 displayed updates to 89/90; this is
synthetic preview validation, not a physical conferencing latency measurement.
