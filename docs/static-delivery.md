# Static and single-file delivery

Community has a Linux x86_64 static build pipeline in
[release-static-linux.yml](../.github/workflows/release-static-linux.yml). It keeps
`X11=1`, `WAYLAND=1`, and `PANEL=1`; normal Arch packages use shared libraries.
The [0.10.4 acceptance run](https://github.com/mattmezza/cast/actions/runs/39021760723)
passed the unit and CLI suites, actual X11 capture, panel rendering, and PipeWire
audio capture with runtime shared-library loading rejected. Published assets are
rebuilt and checked from their exact release tag.

## What the Linux static executable contains

[build-static-linux.py](../packaging/build-static-linux.py) builds pinned FFmpeg,
OpenH264, PipeWire, SDL3, SDL3_ttf, and util-linux libraries from SHA256-verified
source archives. Other static libraries come from the Ubuntu 24.04 build SDK.
[static-linux-lock.json](../packaging/static-linux-lock.json) records the upstream
source URLs and hashes. The build uses the matching PipeWire headers and metadata,
rather than combining a newer archive with older distribution headers. Missing
Wayland and xkbcommon archives are built from the exact installed Ubuntu source
package versions, with authenticated source archives retained for rebuilding.

The final executable links with glibc and `-static`. Release validation rejects any
ELF `PT_INTERP` segment or `DT_NEEDED` entry. The link map is regenerated by linking
the payload last, after test executables, so its source inventory describes the
actual release binary. Archive presence is audited before application linking.

The pipeline runs the unit and CLI suites, Xorg capture checks under Xvfb, and native
panel tests. A separate PipeWire test starts an isolated server/session, feeds a
synthetic sine wave into a null sink, records its monitor with the static payload,
and requires nonzero decoded audio. This checks the real client and built-in modules, not
only successful linking. The release workflow attaches artifacts only after all
checks pass; its dry runs retain artifacts without publishing.

The executable asset is named `cast-VERSION-linux-x86_64-static`. Adjacent release
assets provide SHA256 checksums, the source commit, build configuration, ELF
inspection output, and corresponding source archives. The source collector includes
all pinned upstream archives, the complete application source and build recipes,
and the exact Ubuntu source packages owning static archives in the payload's
link map.

## Runtime requirements remain

The static variant embeds PipeWire client modules and SPA factories in the same
allocator domain as the application. Its module loader rejects external plug-ins.
The panel uses SDL's X11 backend with static dependencies and software rendering;
on a Wayland desktop it needs XWayland. Wayland screen capture remains supported
through the desktop portal and PipeWire, independently of the panel's backend.
GPU driver loading, libdecor and optional controller/audio discovery are disabled. Recording
audio uses the application's PipeWire adapter. The static panel omits SDL's
D-Bus IME integration; UTF-8 text and ordinary keyboard/paste input remain.
PipeWire configuration and a running PipeWire server are still required. These
checks do not establish compatibility with every Linux distribution.

Screen capture still needs an X11 or Wayland desktop session. Wayland capture also
needs the desktop portal and compositor. Virtual-camera output needs the separately
installed `v4l2loopback` kernel module and its device. Network certificates,
keyboard layouts, and composition-text fonts remain host resources. Bundled Inter
covers the panel, not every selectable output font.

The macOS release is a separate `.app` ZIP containing its application and required
non-system dylibs. It is a standalone application bundle with normal macOS framework
requirements; it is not the Linux static executable.

## Auditing other build inputs

The read-only inventory remains useful for another SDK or Pro configuration:

```sh
python3 tools/check-static-deps.py --edition community
python3 tools/check-static-deps.py --edition pro --lgpl-root build/deps-lgpl-candidate
python3 tools/check-static-deps.py --edition pro --stt 1 --lgpl-root build/deps-lgpl-candidate
```

`--x11`, `--wayland`, and `--panel` default to `1`. `--json` emits the report;
exit status `2` means inputs are missing or cannot be inspected. These commands
neither download dependencies nor prove runtime completeness.

## Pro distribution materials

The private Pro implementation remains separate from the MIT Community sources.
The Community release workflow does not publish private Pro artifacts. The private
repository has a separate static acceptance workflow using the same verified
media SDK, production public license trust, and a statically linked CPU Whisper
helper. Pro acceptance and release qualification remain separate.
Pro speech processing also uses a separate structured helper and explicitly
selected model/VAD assets; static desktop linkage would not embed those inputs.

The private static kit includes corresponding library sources and application
object files, library archives, and relinking commands for the application and
helper. The builder verifies that relinking reproduces the delivered executables.
Private source is not included in public Community archives. A shared-library
source bundle does not replace the static kit's relinking materials.
See the [GNU LGPL static-linking explanation](https://www.gnu.org/licenses/gpl-faq.en.html#LGPLStaticVsDynamic)
and the [LGPLv3 combined-work requirements](https://www.gnu.org/licences/lgpl.html).
